# Native metadata statement reuse candidate

The fresh repaired-head profiles attribute 65/57 steady-turn CPU signals to SQL preparation without a live subscriber, and 103/113 with one, for short-small/short-large respectively. Native owners include selected-input manifest headers, readiness frontiers and marks, trace totals, and trace-event location/save queries. The full profiles and diagnostic overhead are in the [aligned observer report](aligned-observers.md).

This isolated candidate uses rusqlite's existing `prepare_cached` path for the closed SQL vocabulary in those four modules. The trace-event lookup helper now accepts only static SQL strings. Statements remain owned by their existing connection and use its unchanged default **16-entry** bound. Every invocation binds its native parameters and reads actual rows. No result/source/body/witness cache, connection owner, transaction/publication boundary, native authority, persisted layout or development gate changes. Native error propagation is retained. This is separate from incremental live display reuse and demand-prepared deep inspection, which remain unfinished.

**122 distinct targeted tests pass**, including manifest/topology, native indexed facts, historical reading, lexical/navigation/cold physical Source bounds, and native tamper/unavailable/readiness negatives. The new differential test compares cache-disabled and default-capacity connections: it observes preparation on the first read, zero additional preparation for the selected warmed SQL at a different historical cut, actual owner-hole changes after native marks, and a read error when the authorizer changes after warmup. Cache-disabled reads still prepare. This tests preparation reuse rather than cached result reuse. The isolated fixture does not claim that an entire runtime workload fits in 16 entries; eviction and complete-process memory/costs must be measured.

The first fixture used a TurnStarted event without its required turn identity and failed before reaching cache assertions. The corrected fixture uses valid native AttemptStarted identities. Both failed logs and the original executable are retained losslessly. The production file hashes match between the original 94-pass/36-negative batches and corrected-regression executable. Nine tests overlap; the union including the new regression is 122, not the sum of batch counts. No deadline, assertion or production behavior changed to correct the fixture.

All-target/all-feature Clippy, formatting and whitespace checks pass. Correctness builds use release dependencies with root opt-level 0; they are not timing builds.

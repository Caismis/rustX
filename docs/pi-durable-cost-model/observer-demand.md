# Display hydration follows observation demand

An unobserved live Runtime Client previously refreshed the derived transcript/trace/occupancy head after dirty native cuts. The worker now schedules these reads only for a registered subscriber or an explicit checkpoint request. Semantic observations, cursor publication and bounded replay continue through their existing owner. This is the first observer-cost change; it does not implement incremental live-head reuse or lazy deep-inspection indexes.

A live explicit checkpoint coalesces one demand and waits for the existing worker's exact source fence and publication installation. The existing deadline, source failure, cancellation and physical-read join rules apply. A stale read cannot clear newer demand. Subscriber registration wakes the worker without doing Store I/O under the attachment lock. Construction still prepares its initial view. No durable layout or client protocol changes in this step.

Deterministic tests gate physical read entry/release and worker turns. They prove no unobserved read, checkpoint demand waiting for installation, and contiguous retained semantic replay on late subscription. Existing physical-read lifetime fixtures now explicitly request the observation whose cancellation/join they test. The enqueue/settlement fixture waits for its existing projection settlement barrier before asking for a completed snapshot; its exactly-once admission and pending assertions remain intact.

Validation uses a real library test executable with root opt-level 0 for local correctness only; formal measurements require the unchanged normal optimized release settings. Projection: 84 passed. Host: 98 passed, including five source-recovery tests; recovery was also run separately. App Server: 296 passed across manager, configuration, protocol and real transports. These suites total **478 distinct passes**. Matching real child executable prerequisites were corrected after initial failed diagnostics; all original logs are retained. Formatting and whitespace checks pass. Matched measurements and exact-head FULL/Merge remain pending. No performance or Pi-parity claim is made for this unmeasured change.

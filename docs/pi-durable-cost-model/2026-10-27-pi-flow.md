# 按 Pi Durable 的 commit → adopt 流程改造 rustX

2026-10-27。本轮已经实现并验证连接内发布就绪状态、固定首轮原子提交、流的首次实际写入准入、按需字段预览、请求验证复用及索引清理。普通无中途 flush 的热请求从 **13 次主库写提交降到 5 次**，与同场景 Pi Durable 相同。真实 WAL frames 降低 **23.21%–25.03%**，正式热请求完整进程写入降低 **29.34%–30.86%**。

**整体性能仍未追平 Pi。** 新鲜独立比较中，四个热请求场景的平均耗时配对比值中位数为 **4.85–5.33×**；以产品内轮次中位耗时比较则为 **5.70–6.32×**。提交次数相同后，rustX 每次提交仍触及更多历史/检查索引页，并继续承担发布编码、历史响应装饰及实际存储认证。不能把这次流程改造说成全部冗余已经消失。

## 本轮实际删除的重复工作

| 原有额外工作 | 当前实现 | 保留的约束或明确改变 |
| --- | --- | --- |
| 原生事实提交后，再持久写 ready/direct 安装进度 | 连接内 MEMORY TEMP epoch，提交后的 release 不再写主库/WAL；新连接直接采用已提交 J/T 基线，不复制旧历史 | 当前连接仍必须安装成功才发布；独立重开不再恢复旧进程的安装/通知完成状态。这是采用 Pi 持久性模型的有意变化 |
| 首次 AttemptStarted、TurnStarted 分别提交和安装 | 固定两个有序事实共用一个事务、receipt 和投影安装 | 原始回调仍按 Attempt→Turn 执行，但 Attempt 回调时数据库已包含 Turn。预取消保持单独 Attempt；真实请求启动仲裁、失败回滚和 SIGKILL 恢复保留 |
| provider 开始时先写一条空 stream | 先建立冻结 generation 的内存 owner；第一批 frames、terminal、audit 或最终结算在同一事务内准入 stream | 首写失败不留孤立 stream；没有持久输出/结算的进程死亡不再产生空流审计。显式空 audit 结算仍支持，已持久输出仍可恢复 |
| 每个普通 request-source 字段提前构造并保存 Fact.header 镜像 | 普通 Fact 只存 geometry/key，读取时从保留的原始字节按需生成原格式 bounded preview | F/C 定位、原始数字/字节、历史 cut、Template 特有 header 保留；普通预览现在依赖对应 raw page，损坏会失败，原生请求/J/C 恢复独立 |
| 一个事务内重复搬运、hash、decode 相同请求配置 | 新写入持有精确序列化 bytes；事务内首次 typed 验证后复用 Arc，每次使用仍比较当前 SQL cell 的类型、长度和完整 bytes | 不跨事务缓存授权；metadata/root/started/completed 等当前证据仍检查；被改写的配置重新完整验证 |
| 冻结 snapshot 时深复制未变的原始 capability/tool JSON | 原始 CapabilityView 用 Arc 共享，更新时替换 owner | 旧 cut 保留旧原始页，超预算/无效条目的分页及 wire/schema 不变；不是用规范化 head 替代 raw header |
| 重复 B-tree 与固定 SQL 编译 | 删除 7 个重复索引；6 个独立 hole 索引合成 2 个 VIRTUAL bitmask 索引；剩余 45 种固定业务 SQL 复用 prepared plan | 当前结果不缓存；全部 mask/cut、实际 seek、回滚与损坏检查保留。生成列的 preupdate ordinal 用 table_xinfo，避免误使原生证明失效 |

入口：[connection readiness](../../src/durable/sqlite/observation_readiness.rs)、[first-turn transaction](../../src/durable/sqlite/attempt_start.rs)、[native request](../../src/durable/sqlite/native_request.rs)、[request fragments](../../src/durable/sqlite/observation_request/composed/fragments.rs)、[preview reads](../../src/durable/sqlite/observation_request/composed/read.rs)、[hole indexes](../../src/durable/sqlite/event_holes.rs)、[raw capability owner](../../src/runtime_client/snapshot.rs)。归档中的 `final-code-review.md` 和 `report-source-review.md` 保存完整调用链与回归说明。

TEMP 不是零成本或常量空间：当前 epoch 新增 J/T 的 ready/direct 行仍驻留，规模为 **O(epoch J+T)**，重建 owner 时清理；SQL、锁、精确洞与唤醒也仍存在。独立只读连接看不到这些 TEMP 表，因此主库逻辑列统计的“缺席”没有填成零内存。本轮匿名 PSS 大部分配对中位数下降，但 live cancel 为 **+0.21%**；长时间不重建 owner 的空间增长未由这些有限轮次证明有固定上限。

## Pi 与 DeepSeek 的源码依据

Pi 固定为 `90d863f7c1183b965f099855715d6e88c7b8a52c`，参照实际 **packages/durable** 路径。其 [Session](https://github.com/earendil-works/pi/blob/90d863f7c1183b965f099855715d6e88c7b8a52c/packages/durable/src/session/session.ts#L690) 先 `storage.commit`，成功后 `tx.adopt(seq)` 并发布；安装失败不会回滚已提交事实，也不另写“内存已安装”确认。其 [SQLite write batch](https://github.com/earendil-works/pi/blob/90d863f7c1183b965f099855715d6e88c7b8a52c/packages/durable/src/storage/sqlite/storage.ts#L187) 将一组语义写入放进一个事务，[backend](https://github.com/earendil-works/pi/blob/90d863f7c1183b965f099855715d6e88c7b8a52c/packages/durable/src/storage/sqlite/node.ts#L194) 使用 WAL/NORMAL。本轮采用这套提交事实→内存安装→发布的生命周期；没有把 coding-agent 的 JSONL 实现当作 Pi Durable。

DeepSeek 固定为 `687f282e8625c6b8d11ff58211a90524be2e4317`。其 [JSONL persistence](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/session/session-persistence-jsonl/src/index.ts#L1411) 批量写后执行 `handle.sync()`，[checkpoint policy](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/session/session-checkpoint-policy/src/index.ts#L29) 在 dispatch 前 flush。使用 pinned 原生 SDK/session，经 TSX 加载，**SDK idle 不等待最后 flush/fsync，且无 partial-token-text publication**。这是额外参考，不是等持久性比值或内置 CLI 启动排名。close/resume 可读不能证明断电持久性；独立 flush 延迟及完整退出后 write_bytes 不可用。

## 真实写入与编译成本

以下诊断均在 8/64 个历史轮次之后测量 32 轮；各收集器是独立产品。逻辑列值、WAL frame bytes、process write_bytes 是不同量，均不等同于设备实际 I/O。

| 指标 | 小历史：上一版 → 本轮 | 大历史：上一版 → 本轮 |
| --- | ---: | ---: |
| 主库全部逻辑列字节增长 | 1,770,317 → 1,406,290 | 1,826,067 → 1,453,455 |
| request pages/nodes/roots 逻辑增长 | 676,185 → 313,648 | 720,804 → 349,764 |
| 主库 WAL write commits | 416 → 160 | 416 → 160 |
| WAL frames | 9,478 → 7,106 (-25.03%) | 10,414 → 7,997 (-23.21%) |
| WAL frame bytes，含 frame header | 39,049,360 → 29,276,720 | 42,905,680 → 32,947,640 |
| 同场景 Pi commits / frames | 160 / 1,683 | 160 / 1,688 |

主库逻辑列增长减少 **20.40%–20.56%**，并不等于移入内存的就绪状态没有成本。候选 WAL 仍为 Pi 的 **4.222×/4.738×**。SQL 栈观察到 32 次重复的五提交顺序：accept inbound → adopt → Attempt+Turn → request-start → final settlement；独立 WAL 中每 32 轮有 160 次写提交。以下按该顺序作跨采集序位对齐，没有逐笔证明 WAL 事务与调用栈对应，小历史也没有独立的同场 SQL 栈。它不是全部工具、重试或流式路径的事务数，也不是理论下界。

按序位对齐的候选五槽，每次提交的 frames 中位数，小历史为 **11/48/28.5/57/76**，大历史为 **11/51/31/64.5/90.5**。对齐结果指向冻结请求与最终结算写页较多。跨事务重复页约占候选 frames 的 **91.19%/90.70%**；这是相同页在不同提交中反复变脏，不是同一次事务把同一页重复写入。八份 trace 未观察到同事务重复页/原位 rewrite；不能由此断言绝无一次性 cache spill，端点 dbstat 也不能精确归因中间页复用。

同 workload 的 SQL 诊断中，prepare 调用 **4,546→1,784 (-60.76%)**，独立 SQL shapes **49→4**。候选观察到的四种均为事务控制，未观察到业务 SQL 再编译；这是编译次数，不是 SQL 执行次数。主库写入改成 TEMP release 后，部分 IMMEDIATE 改为 DEFERRED，不能把后者的增加当成新增同等数量的事务。

## 仍未追平的具体来源

本轮新鲜大历史 live CPU profile 为 baseline **268**、候选 **258** 个样本，下面是各调用路径的含子调用计数，不能相加当互斥总成本，也不能当调用次数或独立补丁收益。

- **发布编码仍有工作。** `PublicationDraft::encode` 为 **54→61**；候选内部互斥分解为 capture **29**、exact structural length **26**、其他 **6**。capture 包含变动域规范化、attempt、metadata 与预算；exact length 中仍有 metadata 和 event/envelope 的序列化。原始 capability 深复制样本 **7→0**，但这不等于整个发布或冻结已零成本。
- **历史响应装饰确有重复回读。** 候选 `ReadDomainCut` 为 **34** 个样本，其中 response `read_validated` **23**、transcript **9**、其他 **2**。每次 checkpoint read 重新读取最多 32 条 transcript，随后创建只在该调用内有效的 Reader。未变历史 owner 的 role/header、ledger/T 定位、latest member、execution/member、closing revision/retry 等会再次查 SQL。它不是全部天然不可避免；同事务携带已有坐标和事实可减少一部分，跨刷新 owner 复用尚未实现。
- **当前 cut 与存储认证仍须有明确失效规则。** 只按 transcript cursor、已完成状态或配置 digest 缓存结果，会漏掉新的 J/holes、同连接改写或损坏。Pi 风格的内存 adoption 可以继续扩展，但必须把这些失效条件纳入 owner；不能以“已提交”替代所有现用读取合同。本轮没有为这项剩余结构改造伪造已完成结论。
- **每次提交的触页量仍高。** request-source 原始范围索引、native history、事件派生域和现用历史索引仍写入。普通字段预览镜像与重复索引已删除，但不能把这些剩余数据全称为同一个 JSON 副本，也不能将整棵导航树挪到第一次读取并声称 bounded first-read 功能未变。

前轮已经实现普通已认证 delta 的 lazy checkpoint 物化；当前采到 `capture_checkpoint` **不等于每次又完整构造 checkpoint**，没有 fit 样本也不证明没有 fit 调用。新 profile 的 control CPU 反而从 **98→104 ticks**，profile CPU 从 **108→104 ticks**，不支持“发布总 CPU 已下降”的结论。原始分解、输入哈希、补充小历史样本与响应调用链都保存在归档中。

# Statistics 权威与有界历史物化

本轮将统计历史从「每个相关事件保存完整累计元组」改为「独立统计贡献 + 稀疏完整检查点」。完整检查点只在终态或累计 16 个统计事实时保存；任意历史 cut 最多重放 15 条贡献。写入连接拥有事务内的暂存 fold，提交后验证实际新增记录才发布复用资格；普通写入不再为每个事件回读上一份完整统计头。

基线为 `f78d1b51a92bbf98f3bc8dd36752db37f6d4dcd5`，复用上一轮已记录的常规 O3/default-features 二进制（实际编译源码 `09e388f85c3b1605e862fc840ccc7a7e89a75e1a`，src/tests/Cargo 与 f78 相同）。初始生产提交为 `ecf0efa00dd01dc584c5cb31960d972cfe613b51`，最终生产提交为 **`c9d5f73e59abc2601d9f57365157580a635aca10`**，重新干净构建常规 O3/default-features。正确性用根包 O0/all-features 构建不参与性能测量。

## 权威和故障依赖

统计权威明确为 bootstrap/继承基础状态与独立统计贡献；完整检查点是限制读取工作的物化结果。外部连接只把完整检查点中的 turns 改为 44，不再能够定义下一次累计事实。检查点摘要同时绑定完整字节和它所属的紧凑事实，格式合法但摘要不符仍报错。摘要用于完整性校验，并非抵抗同时重写全部权威数据的密码签名。

[贡献](../../src/durable/sqlite/observation_statistics/contribution.rs)保存 kind、秒/纳秒时间、最小开始身份、计时 owner 匹配位、是否有完成响应、usage、generation 与工具耗时。开始时钟的固定 source 路径、时间、sequence 和 presence 信息由事实坐标还原；不重复保存整个公开 Clock。无计数变化但推进观察时间的相关事件仍保留贡献。

原始事件和 native 数据只在贡献准备时取必要信息；历史统计读取不解析 event_json，也不读取 native event_timestamp。事实缺失或损坏不能借助原始正文回放来掩盖。统计仍可独立于原始正文健康状态使用。统计域失败继续与 canonical 消息和 Execution 终态隔离，后两者不因统计失败撤销。

[有界历史读取](../../src/durable/sqlite/observation_statistics/history.rs)先找选中 cut 的统计头，再直接定位检查点并读取至多 15 条后缀事实；两个索引分支分别 LIMIT 16，再做有界合并。成功读取最多取 17 个统计数据行（latest、anchor/bootstrap 和至多 15 个后缀，其中 latest 会再作为后缀读到）；缺口/定位查询另计。损坏输入的两个分支合计也最多收集 32 条候选后再拒绝，不能扫描无界历史。BLOB 在 SQL 层检查类型/长度，保留完整状态公开长度准入。伪造古老 anchor 不会导致先排序或扫描整段历史。

故障依赖范围有意改变：一个贡献损坏会影响依赖它的后续 cut，直到一个**已经存在且可独立验证**的后续检查点；该后续检查点不必重读更早的事实。当前检查点或它所属的事实损坏则拒绝对应统计读取。不能从已失败的 fold 新建检查点来自动修复缺口。旧 cut 仍固定，不取最新统计代替。

## 写入所有权、事务和存储

[连接 owner](../../src/durable/sqlite/observation_statistics/owner.rs)持有 pending/committed certificate。准备时在写事务快照内核对 data_version 和本连接依赖 epoch。提交后仅当实际最新统计事实及可选检查点与暂存的原始字节完全相同，才发布 committed 状态。编码 Vec 在消费者结束后移交，无额外复制。

完整回滚失效；SAVEPOINT 回滚与原生 sequence 重用由依赖变更和最终实际字节证明隔离。统计依赖 UPDATE/DELETE、历史 bootstrap 改写或未知 schema/trigger 会关闭该连接的写 fold 复用；后续正常走有界事实读取。外部提交由 data_version 隔离。公开历史读取从不使用 writer fold 隐藏当前数据库损坏。

初始候选在暂存 fold 后遇到非统计插入或原生游标更新会直接失效。首批净测量没有改善热对话，因此最终候选进一步只在 sequence 重用、游标回退/非法值或游标落后于暂存 prefix 时失效；后续正常非统计插入和单调游标推进保留 fold。SAVEPOINT 回滚后复用 sequence 的回归与正常混合批次零旧头回读的计数回归同时保留。仍保留全状态规范化和公开长度准入；本轮减少完整编码与完整历史物化，不等于取消所有状态遍历。提交发布也有一次读取**新紧凑记录**的校验。

既有 `events.observation_statistics` 改存贡献，新增可空 `events.observation_statistics_checkpoint` 保存完整检查点；bootstrap 仍在既有 store 行。普通事件仍在同一 compound INSERT 中写入，无新表、无新索引、无持久化 current-state 行、无后台补写。既有统计头/缺口索引保留。Execution 的状态、receipt/proof、Request Source 布局和事务边界保持既有实现。

私有 schema **89→90**。按仓库要求拒绝旧数据库，不加入迁移、兼容读取或 fallback。公开统计 DTO 和功能保留；「外部合法改写派生总数必须成为以后统计权威」这一既有内部测试合同明确取消，并替换为派生检查点完整性回归。

## Source 与流式定向解释

先对 `03ec15b4` 与 f78 运行独立的诊断插桩构建，未把插桩带入生产或用于正式提速结论。8 个流式产品每个执行 8 个固定请求，共 64 请求；另有 32 个 A/B/A 与阈值检查产品。

无订阅两对全进程 CPU 为 1090→1040、1080→1070ms，有订阅为 1130→1110、1090→1100ms；请求窗口 CPU 分别为 930→890、940→930、960→960、930→950ms。较长窗口没有稳定复现上一轮 +9.6% 全程 CPU。两组不能合并或用这批数据抹去上一轮反向结果。Live 的 finish→settled 阶段为 60→100、50→100ms，其他阶段有抵消变化；端点为 10ms 粒度，累加八个短阶段的量化误差更大，无法唯一归因某个生产函数。

每个产品请求阶段 Source loads 均为 0；Source 构造/编码 89→25，layout 90→26，全部结构化编码 145→81，geometry visits 178→26。没有发现延后历史 Source 在流式请求里被额外触发的证据。

A/B/A 实验中，旧版本在 append 支付 RuntimeEvent schema/plan 初始化；f78 在第一次 A 检查支付各一次，随后第一次 B 和再次 A 都不重复初始化。但每次仍重新构建 Source，没有跨调用事件缓存。第一次约 2ms 不能乘以历史事件数；这里也不是清理内核页缓存后的磁盘冷读。

阈值诊断证实：native 16,382 字节编码后为 16,384，仍走内存；native 16,383/16,384 编码后为 16,385/16,386，f78 每次读取都新建临时索引，重复读取约 420–432µs，旧 eager 路径约 11–13µs。native 16,385 又回到 eager 分段路径。生产候选将延后 native 上限改为 **16,320 字节**，预留 64 字节；九个闭合事件族最多 11 个需加引号的无符号标量、最多增 22 字节。准入只看已准备的 native 长度，不为判断准入再完整编码。覆盖九族最大合法数值及精确边界的回归防止字段扩展无声破坏预算。

## 初始候选的净结果与修正

初始候选 ecf0 的 72 个产品全部成功，独立复算接受 32 正式产品、16 配对和 1,088 对请求。热对话轮次耗时的配对变化中位数为 +1.168%、+2.971%、+7.034%、+1.978%（依次无订阅短/长历史、有订阅短/长历史）；完整进程 CPU 为 +0.602%、−1.400%、+2.162%、+0.334%。这批数据不支持宣称热对话提速，全部反向对均保留。

其中正常 TurnCompleted/原生游标推进也会使 pending fold 失效，因此终态前会重新加载有界统计后缀。最终 c9d5 只在推进不能证明保留 prefix 时失效；正常 mixed batch 的回归计数为两次 fold hit、零旧统计记录读取，而 rollback/reuse 回归继续通过。该修正之后重新独立测量，不把两批样本混合。

初始列诊断每 32 个热轮：完整统计 tuple **192→32（−83.333%）**，短历史统计 **56,993→18,647 字节（−67.282%）**，长历史 **57,471→19,086（−66.790%）**；候选分别另有 192 个紧凑事实。全表逻辑列值 **1,049,874→1,011,517 / 1,075,825→1,037,444**，下降约 3.65% / 3.57%。这些逻辑字节不是可直接等同的设备写入。

实际 WAL 总帧 **5,666→5,657 / 6,382→6,391**；events 页帧 **288→280 / 288→288**，两种历史下均为 **160→160 次写提交**。短历史确有少量页帧减少，长历史未降低；其他索引页变化也会影响总量。因此不能把统计列缩减 67% 宣称为 WAL 同比缩减。进程完整周期写入四格仅 −0.334%、−0.095%、−0.316%、−0.052%。

普通 O3 阈值检查（每侧两产品）：native 16,383/16,384 字节的重复读取中位值 **408.190→10.631µs / 411.824→10.694µs**；首次 **2,415.909→37.276µs / 2,347.103→36.216µs**。独立 strace 产品中，读取窗口内的临时 index.sqlite 创建次数均 **9→0**。16,320 字节仍延后、首读约 1.83ms/重复约 35µs；16,321 字节转 eager，首读约 88µs/重复约 36µs。时间与临时索引计数分别来自普通和 strace 产品，不混用插桩时间。

## 最终候选的净结果

最终 c9d5 的 52 个产品全部成功；严格复算接受 32 正式产品、16 配对、1,088 对请求，12 个 Statistics 产品及八个列/WAL 产品。下表百分比为逐对变化的中位数，不是两侧中位数之比。

| 情形 | 轮次中位耗时 | 全进程 CPU | 全周期进程写入 |
|---|---:|---:|---:|
| 无订阅，8 轮历史 | -3.552% | -1.758% | -0.287% |
| 无订阅，64 轮历史 | +5.395% | +2.857% | -0.114% |
| 有订阅，8 轮历史 | -0.524% | +0.006% | -0.334% |
| 有订阅，64 轮历史 | +2.656% | +0.831% | -0.132% |

**这轮实现了统计物化减量与 Source 边界修复，但没有证明整体热对话加速。** 无订阅长历史四对轮次耗时全部升高，范围 +3.615%…+11.334%；其全 CPU 四对也全部升高。其余三格有反向/零值，详表全部保留。不能用局部的 −3.552% 或 67% 字节缩减掩盖这些结果，更不能宣称追平 Pi。

最终列诊断每 32 轮：完整 tuple **192→32**；短历史统计 **56,993→18,654 字节（−67.270%）**，长历史 **57,477→19,128（−66.721%）**，新侧分别包含 192 个贡献与 32 个检查点。全表逻辑列值 **1,049,875→1,011,535（−3.652%）/ 1,075,838→1,037,486（−3.565%）**。完整编码计数、紧凑事实和检查点行数由单元计数与实际 SQL 两种证据覆盖。

最终独立 WAL 诊断总帧 **5,669→5,656（−0.229%）/ 6,390→6,376（−0.219%）**；events 页帧 **288→280 / 288→288**，每 32 轮仍为 **160→160** 次写提交。只有一份每侧每情形 WAL 诊断，不据此声称总体稳定下降；初始候选长历史的 WAL 反向结果也未删除。四格全周期进程写入降低仅约 **0.11%–0.33%**。没有增加 current-state 行，也没有获得与统计列字节相同幅度的页写收益。

原因应按实际规模理解：完整统计在基线全部逻辑列值中只占约 5.3%–5.4%，本轮总逻辑数据只减约 3.6%；大部分行、索引、写提交和其他派生域工作仍需维护。同一个页仍被弄脏时，少几百字节不会省掉该帧。另一方面，非检查点 cut 现在需要定位检查点、读取多个紧凑记录并应用后缀；提交发布仍有新记录验证，公开准入与全状态规范化也保留。这些新增或保留成本可以抵消少编码的收益。现有数据没有函数级归因，不能把长历史 +5.4% 精确分摊给其中一项。

## Statistics：完整记录与事实权威

每条相关事件保存一个完整统计状态和它的独立统计贡献，放在一个有界 BLOB 内。固定绑定前缀将行 sequence、贡献长度、贡献和完整状态绑定；两个组件沿用既有 MessagePack tuple 和各自的公开 JSON 准入。旧格式、旧列和旧读取分支均移除，不保留双读或迁移。

历史 cut 使用原有共享 head 索引选择一条记录并验证当前存储字节，检查选中记录之后是否有缺失贡献，不再重放后缀。初始化／继承历史仍使用原来的完整基础状态；bootstrap48KiB上限没有扩大。组合事件记录物理上限98,340字节，对应此前两个独立48KiB组件及固定绑定；公开统计准入没有扩大。

writer 的 pending／committed fold 和提交后实际字节验证保留。真实回滚、savepoint、sequence重用、外部修改和只读 rollback 的失效边界保持；合法改写累计总数而不保持事实绑定，不能成为未来累计依据。公开读取不使用 writer 内存状态冒充当前存储证据，不读取 event_json 或原始事件时间作为统计恢复兜底。

故障依赖现在更直接：某条记录损坏会使选择它的 cut 失败；后续独立完整记录仍可使用。选中记录之后缺失必需统计事实仍失败。统计域失败继续不撤销 canonical 消息和 Execution 终态。绑定是当前存储完整性检查，不是恢复独立原始捕获认证。

独立 Statistics 对照：64事件 cut63 重复读取约28.5→11.0µs，reopen后约30.9→11.6µs。短／长历史32热轮 WAL7000→6995、7772→7786帧，写提交均160。统计逻辑字节18,823→73,306及19,292→74,047：完整物化更多，但这次2KiB布局的页维护变化很小。热轮完整原值见数表，不将旧版5%反向数据当作本次能收回的收益。

## 导航页：保留索引，删除压缩协议

页格式只保留一种完整 UTF-8 key 表示，使用一个实际字节预算。64KiB页、64项fanout、4160字节key、40KiB value、深度、排序、EOF、hash和旧root不可变检查继续存在。跨页全局排序检查保留；被删除的是页内前一个 key 依赖。

这是私有存储格式更新，最终 schema96明确拒绝旧开发库，不引入迁移或兼容开关。事件 evidence、私有 request record、Statistics／Execution tuple及长度证书不随之撤回。完整key在长公共前缀输入上会占更多逻辑字节；实际Source页、overflow和WAL的当前对照必须单独看，不能从编码比例推导磁盘写入。

限定复测的四格热轮耗时变化为：无订阅8／64历史 **+6.92%／−6.52%**，有订阅8／64历史 **+3.50%／−0.71%**；对应CPU为 **+8.89%／−1.85%／+3.45%／−1.56%**。短历史反向项保留，不称为整体加速。导航页增量行数仍为165／160；逻辑字节76,849→78,896、71,424→71,104；Source表overflow净增长均为零。导航独立WAL6995→6997、7786→7800帧。完整key没有造成显著页写扩大，简化价值来自删除压缩协议。

### 异常和归因边界

首轮导航矩阵出现最长4.6秒的单轮和长历史+216%的配对均值；相同旧ELF也有百毫秒峰值。同期无关工作树的全量测试占用约8核，一秒写入60,768,256字节，系统I/O压力很高；未加载会话／未执行Source的创建阶段也由历史约2秒抖到147秒。这一矩阵原样保留，不能当作prefix代码的因果证据。

停下后续采样，待该测试结束后进行了一次32产品热轮复测，并将固定复核补到四组。前置记录显示设备即时忙碌约0.32%，但全局PSI仍高，**不声称独占主机或完全消除环境影响**。新增固定第0组候选仍有82.43ms单并发／22.5ms CPU异常，第1组回到10.59ms／11.25ms，第2组单并发9.46ms；所有值均进入数表，未删除或只挑好结果。两组深历史耗时的配对一升一降，展示中位变化+224.56%受173.82ms那一格支配；它同样保留，不能据此承诺深历史延迟无退化。

因此本轮结论是“机制更简单、历史读取更直接、内存与写入收益基本保住”，不是“性能全面提升”。短历史CPU、单并发延迟和冷恢复的反向值是评审应看到的代价／不确定性；本轮不再据此扩展新的缓存或优化方案。

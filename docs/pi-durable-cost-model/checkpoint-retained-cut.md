# Checkpoints retain their captured native cut

FULL [39184296007](https://github.com/Caismis/rustX/actions/runs/39184296007) at `1b32165c1c771d0941bb3565024bcffc5c6b61be` exposed two regressions in the initial observer-demand stage. Parent source review identified the moving-fence path; developer-run reproductions cover both classes.

* A checkpoint requested worker hydration before capturing a published seed. Two ordinary native transitions could move that fence twice and exhaust the existing two attempts even though the original published cut remained serviceable. A deterministic test gates the worker read and admits exactly two native inputs between capture and fence validation. It fails with `ReadCutExpired` on the previous production code; no sleep or timing-based verdict is involved.
* A dirty checkpoint depended on worker progress even when the caller deliberately held a native compaction release, or synchronously inspected the host on a current-thread executor. The existing manual-compaction and shutdown-settlement tests reproduce `checkpoint Source repair deadline exhausted` on the preserved previous executable. The related lost-commit-ack fixture passed that local red run and failed in CI; both results are retained.

Ordinary checkpoint inspection now captures the existing immutable published seed first, hydrates its bounded transcript, occupancy and trace heads outside the host lock, and validates that retained cut after materialization. Native publication can continue without forcing the request to chase the live head. This changes no execution authority, persistence boundary, retry limit, deadline, executor flavor or durable/protocol layout. A known Source failure still requires the existing worker-owned successful repair and publication installation. Subscribers retain their worker-owned hydration and cancellation/join behavior. Closed-host inspection uses the same request-owned path introduced by the shutdown repair.

The regression checks exact frozen transcript, occupancy and projection values, one captured cursor despite two real native admissions, and contiguous replay of the concurrent publications. The dormant-demand test now proves that inspection hydrates a request-owned seed without installing a live derived head. Existing shutdown and Source-repair tests remain part of validation. Removing the obsolete asynchronous shutdown wait keeps the shutdown test below the lint limit; the separate parked-worker test still proves synchronous native shutdown publication.

The wait captures the publication generation before reading the published seed, releases the state lock before waiting on the existing condition variable, and rechecks the mutation predicate after wakeup. It does not poll or request a projection-worker read. A closed owner is rejected at the next predicate check (at worst the existing deadline when no further publication wakes the waiter). This synchronous API has no separate caller-cancellation token. Valid frozen-cut inspection still completes without that owner or worker, as the unchanged manual-compaction/current-thread shutdown regressions verify.

# 有界事件观察延后与聚合缓冲区复用

本轮把常见小事件的完整 Source 编码、字段几何解析及 overlay 构造移出普通事件写入路径。原始事件仍同步持久化；写入时直接从类型生成必要观察头，并保存一条 33 字节的表示记录（tag + 原始事件 SHA256）。查看该事件时才在单次读取的快照内验证数据库当前字节、解码并构建有界 Source。统计及执行聚合继续查询并校验当前数据库单元格，但不再先复制整个旧 BLOB；统计的新编码在同一事件的消费者结束后直接转交缓存。

这是附件建议的第一阶段：消除重复准备和编码缓冲区周转，并在闭合、可无损重建的事件族上建立明确的延后边界。尚未把大 Request 的完整 Source 改成延后建立，也没有改成统计增量日志；不能把这些未实施的架构变化写成已经完成。

基线为 `03ec15b4bccccc9459fd1ec7b7fdd1bf4673a617`，生产源码为 `09e388f85c3b1605e862fc840ccc7a7e89a75e1a`。两者均重新构建常规 O3、默认 features 二进制；测试用的根包 O0/all-features 二进制不参与性能测量。

## 同步写入与延后工作的边界

[事件 Source](../../src/durable/sqlite/observation_event/inline.rs)的原生引用表示只用于明确列举的闭合事件族：AttemptStarted、AttemptTimedOut、TurnStarted、TurnCompleted、ModelRequestStarted、InboundTurnAdopted、AssistantMessageCommitted、AttemptCompleted、ModelRequestCompleted。原始 JSON 必须在 1–16,384 字节内。原始内容不可变这一语义没有变成“相信内存里的旧对象”：每次检查仍读取当前事件和当前表示记录、验证原始字节摘要、sequence 和事件族，然后重建 Source。整个操作处于既有读取事务内。

[必要观察头](../../src/durable/sqlite/observation_event.rs)直接准备类型和短 finish reason；identity、usage、generation、terminal 信息继续使用既有类型路径。大于 256 字节的未知 finish reason 保留原有字段预览/延后规则。不能安全走直接路径的事件仍使用既有精确 Source 准备。

复杂事件使用同一私有列里的另一种当前表示：tag 1 + 精确 overlay。这不是旧数据库兼容层。举例说，ToolProgress 中 `Some(NaN)` 序列化为 null，但类型回读会得到 None，重新输出时可能省略该字段；直接重建会改变历史 Source。新增回归验证 NaN/Infinity 的原字节、分页和字段范围，并拒绝把这类事件伪装成原生引用表示。

大于边界的事件仍同步建立分段布局，避免首次读取一个小字段时遍历无界历史。没有后台构建器、持久化 inspection cache、跨调用 Source 缓存或新授权捷径。未知 tag、摘要不符、错误类型/事件族和损坏表示均报错；不会把损坏当成“尚未建立”，不会回退到最新状态或重新捕获当前输入。

## 聚合复用

[read_fold](../../src/durable/sqlite/append_facts.rs)在 SQLite 借出的 BLOB 上完成全字节比较，cache miss 时也直接从该借用解码。[Statistics](../../src/durable/sqlite/observation_statistics.rs)和[Execution](../../src/durable/sqlite/observation_execution.rs)仍运行原有当前状态查询、缺口/损坏检查与历史 scope 规则。内存缓存只是经当前字节验证的解码提示。

[同一事件完成准备后](../../src/durable/sqlite/event_insert.rs)，Statistics 将已供 INSERT 和其他消费者使用的新编码 Vec 转交缓存，省去原先的第二份字节复制。Execution 的新编码仍有它现有的多消费者所有权；没有为了消除一次复制引入共享 owner 抽象。Statistics 仍保存每次事件的完整有界统计元组，未采用增量持久化，也未删除统计历史。

## 功能与存储约束

原始事实、冻结输入/配置、顺序、取消、usage、terminal、恢复和独立 native/Source/Trace/statistics 故障边界保留。普通热轮的事务数量和 WAL/NORMAL 不变。Source 延后没有引入后台写入。

私有 SQLite schema 从 88 升为 **89**，`observation_source_overlay` 替换为 `observation_source`。按仓库规则拒绝旧数据库，不提供迁移、兼容 reader 或旧布局 fallback；这是一项明确的存储格式变更。公开观察 DTO 未变。

## 验证

16 项检查命令通过：**2,363 项不同测试 passed、0 failed、1 项既有 ignored**，Fmt 和 release/all-target/all-feature Clippy（`-D warnings`）通过。包括 SQLite 644、runtime client 616、72 项真实进程死亡、151 项 durable integration、62 项 process integration、8 项 artifact lineage。新增四项回归覆盖直接路径工作计数及独立 oracle、finish reason 边界、非有限标量和 schema 拒绝。

字段/分页 oracle 对照原来的独立分段构造；历史 cut、reopen、当前字节修改、后续授权拒绝、外部 writer 快照、独立派生失败和回滚回归保留。最终检查与常规 O3 构建绑定同一组 966 个 src/tests/Cargo 输入。早期的旧版本号 fixture、SQLite 表达式索引先行拒绝的攻击 fixture、两项 Clippy 失败和修复输出保留在证据中，未计为最终通过。完整仓库 CI/browser E2E 和 main 合并不在本轮验证范围。

## 测量方法

只执行 Rust 基线和候选。六种情形 × 两种订阅模式 × 每格四对，执行顺序各两对 before/after 与 after/before，CPU 2、8：**96 个正式产品、48 对、1,128 对请求**。每格保留全部四对、反向结果、零值和缺失计数；只报告描述统计，不据四对样本宣称总体显著提速或 Pi parity。已有 benchmark 不包含 AppServer 传输。全程 CPU/写入包含基准进程内的输入与观察 oracle、重开检查及清理；settled 耗时与这些全程计数分开。

另执行 **32 个独立历史检查产品**：小事件、10KiB 叶字段、32KiB 分段事件、并发对话/检查，各四对。每个产品先写 64 个事件，再首次读取旧事件字段、重复 32 次，首次根分页、重复 32 次，并验证 reopen。并发情形额外追加 32 个事件、同时读取旧 cut 64 次。字段读取对照预期值，重复分页对照本产品首次页；与独立旧分段构造的完整对照由单元回归覆盖。没有跨调用缓存。这里的“首次”是进程内首次 API 检查，不是重置内核页缓存后的磁盘冷读。时间包含公开 API 及断言/结果比较；所有产品使用同一 probe 源码和分别链接的 O3 库。

另执行 **8 个列/WAL 诊断产品**。列值字节、WAL 帧、进程 write_bytes 是不同量；不能把某列逻辑字节减少直接解释成等比例设备写入下降。WAL 解析器在新测量前已用四份保留旧 trace 验证，并严格核对每帧 24 字节 header 和 4,096 字节 payload 的数量及 offset；未重跑旧产品。

正式与诊断、检查阶段分开，不与编译/正确性检查重叠。CPU 计数端点粒度为 10ms；记录 affinity/topology 和子进程继承约束，不声称独占机器或连续采样每个线程的驻留。

[全部单元、四对原值和不利结果](2026-11-03-observation-boundary-tables.md)及[原始证据与可移植复算](evidence/observation-runtime-20261103/README.md)均保留。Pi、DeepSeek 均未重跑，固定参考仍为 Pi `90d863f7c1183b965f099855715d6e88c7b8a52c` 和 DeepSeek `687f282e8625c6b8d11ff58211a90524be2e4317`；不把旧的非固定 CPU 批次与本轮拼成新倍数。


## 本轮结果

全部 136 产品退出成功并通过各自校验，最终校验通过：96 正式产品、48 配对、1,128 对请求；32 历史检查产品；8 列/WAL 诊断产品。以下百分比均先逐对计算后取中位数。

| 热对话情形 | 轮次中位耗时 | 全程 CPU | 全程进程写入 |
|---|---:|---:|---:|
| 无订阅，8 轮历史 | +0.974% | +0.610% | +0.029% |
| 无订阅，64 轮历史 | −1.988% | −0.898% | −0.011% |
| 有订阅，8 轮历史 | −6.831% | −3.707% | +0.006% |
| 有订阅，64 轮历史 | −4.161% | −1.670% | +0.027% |

三个改善的热对话单元均为四对全部较低；无订阅短历史有反向结果。整个正式矩阵的轮次中位耗时为 **33 对降低 / 15 对提高**；全程 CPU 为 **21 降低 / 16 相等 / 11 提高**；进程写入为 **15 降低 / 26 相等 / 7 提高**；采样 RSS 为 **34 降低 / 14 提高**。这是本轮描述统计，不能据此宣称所有场景更快。

两种 large 单请求的耗时中位变化约 −6.97%；无订阅 stream 的耗时 **+1.505%**、全程 CPU **+9.583%**，有订阅 stream 耗时 **+0.068%**、全程 CPU 中位变化 0%。这些结果与各对的范围都保留，没有追加有利样本、替换单元或与旧批次合并。

每 32 个热轮的 256 事件，Source 私有列值字节 **19,968→8,448（−57.692%）**，即每条 78→33 字节；原始 event_json 字节分别保持 101,025 和 101,120。两种情形全部表的逻辑列值增量分别 **1,061,407→1,049,883** 和 **1,087,370→1,075,828**。逻辑表示更小，但普通流程仍修改相同的数据页/索引并保持原事务边界，所以本轮**没有证明整进程写入量实质下降**：热对话四格的写入变化仅 −0.011%…+0.029%。独立 WAL 诊断也只有 **5,665→5,664 / 6,387→6,391 帧**；每 32 轮仍为 **160→160 提交**。不能把 57.7% 的 Source 列缩减宣传成总写入缩减。

### 历史检查的成本转移

| 独立检查情形 | 64 事件追加 ms，旧→新 | 首次字段读取 µs，旧→新 | 重复字段读取 µs，旧→新 |
|---|---:|---:|---:|
| 小事件 | 12.834→10.239 | 58.937→1,856.737 | 8.426→10.200 |
| 10KiB 叶字段 | 18.052→17.401 | 84.358→128.248 | 26.738→27.261 |
| 32KiB 分段字段 | 67.676→69.088 | 71.377→72.249 | 25.884→25.591 |
| 并发产品的初始追加/检查 | 12.962→10.171 | 60.084→1,851.969 | 8.416→10.128 |

表中是每侧四个产品值的中位数；不是配对百分比，也不是磁盘冷读。小事件首次检查明显更慢，重复检查约增加 1.8µs。原来写入阶段执行的结构化编码与 schema/plan 首次准备现在可延后到首次检查；本探针未把其中每个内部步骤分别计时，因此不把整个首次差额归因给某一个函数。工作始终限于一个 ≤16KiB 原始事件，不随之前 64 个事件的总字节增长，也不扫描请求历史。32KiB 情形继续使用原分段路径，未声称其受益。

并发阶段，追加 32 事件的中位时间 **3.831→3.341ms**，64 次历史读取的产品内中位数再取中位为 **9.020→10.214µs**。全程 CPU 的 10ms 粒度不足以量化这些小差额；四对结果在表格中保留，不据此声称精确的检查 CPU 节省。32 个检查产品的首次/重复字段及分页阶段均为 **0 新增 write_bytes**；并发写入计入全程写入。完整周期的写入在各对应产品间相同，没有后台补写。

这轮确认的是减少每轮提前构造的观察材料、减少表示字节与缓冲区复制，并测出了所转移的首次/重复检查成本。大 Request 的分段 Source、统计完整历史元组和现有事件索引仍保留其职责；本轮结果不支持“已经追平 Pi”或“总写入显著减少”。

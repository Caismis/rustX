# Compact resident Source navigation

The fresh counter profile found one 12–13 KiB request-scalar Source per short turn still constructing a temporary SQLite navigation index although its exact bytes fit the resident carrier. Compact checked coordinates now admit Sources up to 16 KiB within the existing conservative 1 MiB navigation-memory allowance. Larger Sources retain the disk-backed path and bounded physical reads. This is an isolated representation change, independent of the newly authorized lazy-inspection/display-view architecture.

The internal compact representation uses checked u16 IDs, parents, ordinals and byte coordinates, and a checked u8 saturated preview-node count. Reads expand into the existing u64 API. At most 8192 nodes can occur in 16 KiB of valid JSON; the compile-time memory bound includes vector capacity, sealing child counts and decoded key capacity. Original bytes, raw lexical JSON, key order, paths, pagination, reader pins and persisted formats are unchanged.

Validation: **85 distinct tests passed**: 26 Source navigation tests, 26 composed request tests, six state-preview tests and 27 durable content boundary tests. Coverage includes exact 16 KiB admission boundaries, a worst-density 8192-node tree, compact/disk differential traversal and full spans, lexical RawValue/u64 evidence, original reader ownership and cold bounded reads. The source-error fixture still exercises both storage backends after the threshold change. Formatting and diff whitespace pass. Test-only compilation uses root-package opt-level=0; measured binaries use normal optimized release settings.

# Isolated live Trace demand checkpoint

This stage removes deep Trace page materialization from the live Session-domain worker. It does not optimize canonical append or change Source encodings. The earlier [cloud profile](final-production-profile.md) recorded 153 native read-domain samples among 617 short-small CPU signal samples, alongside 139 publication-encoding samples. Those historical diagnostic stacks guide this experiment; they are not percentages, a fresh final-head profile, or performance evidence for this candidate.

`ReadDomainCut::read_live` reads bounded transcript decoration, occupancy, projection metadata and Trace totals. It leaves the cached Trace page, issued read cut, prepared head and Source pins unchanged. Complete checkpoint reads still materialize the captured published native cut whenever the cached Trace through/source-cut differs, including canonical C without terminal J. Explicit Trace pages/details and generic Source reads retain their authorities and finite cuts. No witness is regenerated and no canonical/event/inspection bytes are discarded.

Runtime Client 72 / App Server 51 represent a Session-only `read_domains_updated.trace` as null. Every current reader/schema/doc advances together, and old versions are rejected. A supplied Trace head can still replace the cache. The browser keeps pending Trace page/detail readers on Session-only updates; a full replacement retaining an older Trace cut requests a separate bounded repair without retiring those readers. A fresh materialized Trace head still replaces its previous authority. `trace_changed` remains independent; Job updates alone do not invalidate Trace caches.

The live worker no longer emits a Session enrichment solely because it materialized a changed deep Trace page. This is the optional enrichment policy under review, not a change to native commit/publication cadence settings, P<U<C ordering, durability, lifecycle ownership or persistence formats. Deep Trace decode/I/O errors are observed on an explicit Trace/current-checkpoint read; known native unavailable/pending Source evidence still fails closed. Runtime commits do not depend on optional inspection success. The change adds no queues, timers, sleeps, retry loops or caches with authority.

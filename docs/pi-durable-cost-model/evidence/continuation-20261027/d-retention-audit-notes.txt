Independent candidate D retention audit (read-only evidence analysis)

Result: raw-data and identity audit passed. Retaining the joint candidate is defensible as a targeted improvement, provided the adverse results below stay in the report. This is not evidence of Pi parity or of general nonregression. No individual benefit can be assigned to either of the two jointly measured changes.

Checks:
- Re-hashed both retained executables; checked source src-tree identities, six identical benchmark-harness hashes, matching compiler identity, and rebuild artifact records (ordinary opt-level 3, debug assertions disabled, no profiling feature, fresh=false).
- Checked all 72 product/controller records, reran their existing semantic validators, and independently reconstructed all 1,692 expected HTTP request bodies from prompts/scripted replies plus the fixed tool schema. Every one of the 846 paired requests is fully semantically equal after the declared exact workspace-path/text normalization.
- Recomputed all eight raw metrics, all 288 paired ratios and 96 summaries, including medians/ranges and stored log-ratio intervals. All match direct-d-recomputed.json. Before/after result mtimes agree with the declared alternating order. The files cannot independently prove absence of unrelated external scheduling activity.

Predeclared gate:
experiment.txt required correctness, useful target gains, and no consistent material wider-cost regression, with no selective reruns. It did not predeclare a numeric materiality cutoff or a minimum count of regressing pairs. Therefore retention is a stated engineering judgment, not a mechanically proven pass. The full three-pair data set is retained; nothing is trimmed as noise.

Observed target gains:
- no-live short-small: wall ratio median 0.840596, per-turn self CPU 0.857143, complete-through-cleanup self CPU 0.904255; all three pairs improve each metric.
- live short-large (64 history + 32 measured turns, not the single-turn large case): wall ratio 0.966770, complete self CPU 0.911215; all three pairs improve wall, per-turn CPU and complete CPU.

Adverse and inconclusive observations:
- live short-small: wall ratios 1.458342 / 1.042027 / 0.965548 (median about 1.042). Pair 0 also worsens per-turn CPU by about 42.4% and complete CPU by about 24.7%; it is not merely a wall-clock outlier. Retained without exclusion or a causal explanation.
- no-live single-turn large: wall ratios 1.146284 / 1.147002 / 0.931130; two of three regress by about 14.6%. Complete CPU ratios 1.058824 / 1.055556 / 0.947368. Per-turn CPU is only 4–6 clock ticks in these runs and cannot resolve fine differences; this does not erase the observed wall regression.
- no-live stream complete CPU median +6.45% (two pairs worse); no-live tool complete CPU median +5.56% (two pairs worse); live tool complete CPU median +4.76% (two pairs worse). Mixed pair signs and coarse short-run counters preclude broad conclusions.
- live sampled anonymous PSS increases in all three short-small, short-large and stream pairs. Median increases are approximately 0.21%, 1.25% and 1.51%; the largest of these paired increases is 2.63%. Small but real recorded differences, not zero regression.
- Process-attributed writes are almost unchanged. Median ratios range close to 1; no claim of a useful write-volume reduction is supported by these samples.
- no-live short-large pair 2 has a very favorable wall ratio about 0.35765 while CPU is about 0.9469. This favorable outlier is retained too and must not be sold as a representative 64% speedup.

Scope and limits:
- CPU counts self user+system ticks at 100 Hz; complete CPU is the absolute through-cleanup value, including startup, harness work, and verification. It is not only measured-turn runtime.
- I/O is /proc process-attributed write_bytes, not device writes. Memory is maximum sampled PSS/RSS across captured phases and turns, not true peak or allocation count.
- Only three pairs: confidence intervals use a log-ratio Student-t model whose distribution and independence assumptions are not established. They do not turn this small experiment into parity/noninferiority evidence.
- Builds/tests/measurements were not run by this audit. Correctness-suite completion is a separate prerequisite owned by root; retained product validation was independently rechecked here.
- Fresh direct D/Pi comparisons are required for any current Pi claim; do not multiply historical ratios.

Artifacts: d-retention-audit.json contains all raw metrics, ratios, identities, hashes, and comparison evidence. audit-d-retention.py is the standalone read-only recomputation source.

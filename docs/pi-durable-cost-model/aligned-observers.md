# Aligned native observer benchmark

Two explicit modes now exercise the production adapters against the same controller-owned sibling HTTP/SSE provider. `no-live-subscriber` has no subscribed display consumer during turns. `live-subscriber` consumes real text, tool and settlement updates. Rust uses LocalConversationRuntime/Runtime Client in both modes; Pi uses the pinned SQLite Harness and production watchEvents. The original App Server/Pi submission-only `native-workflow` remains separately identified. This comparison does not measure complete TUI rendering or equate native transport and schema costs.

Rust consumes inline committed messages, streamed prefixes, checkpoint replacements and full deferred ContentRefs. It checks cursor adjacency, exact visible prefixes, final assistant text, native terminal outcomes and ordered tool results. Journal-owned ToolExecutionSettled counts execution completion; canonical ToolResultCommitted supplies the output body. The consumer cannot assume those separate observations arrive with the same body. A bounded inline display following a full ContentRef must match its prefix and cannot replace the full content. Unchanged old descriptors cannot reset first-content timing. Late observation checks a checkpoint and either complete cursor-contiguous retained replay or explicit ResyncRequired; both paths close the real observer before joining it. Every historical message is then paged through the public cut-bound checkpoint API, resolves deferred content and matches the full ordered native Originals. These full read/verification costs are included in the late-snapshot phase and complete lifecycle, not claimed as pure snapshot latency. Structural JSON's exact decimal encoding of tool duration is compared with the corresponding u64 without dropping digits or other fields.

Pi's consumer folds actual message/block/string-argument updates and tool output, verifies entry order and tool results, and awaits native run completion. Replacement snapshots must preserve previously consumed entries in these non-compacting fixtures; a replacement that ends a known active run resolves its observer wait. Late watch snapshots must exactly equal independently read ordered native entries. Content mutation, missing starts, orphan updates, duplicate entries/completions, changed tool arguments and rewritten replacement snapshots fail the consumer tests.

Cancellation intentionally has no canonical assistant answer. The provider emits `partial`, waits at its cancellation gate, then has a forbidden tail. An engine may expose the partial before cancellation; it must never publish the tail. Rust's observed partial is checked against the frozen request's provisional message identity. Pi's observed partial is retained separately. Their native coalescing/publication differences are preserved, not normalized into equal display activity. First-consumed-publication remains unavailable when no text was delivered.

The external controller independently validates raw/turn/process mode identity, lifecycle endpoints, ordered late messages, live consumer text/tool results and request/reopen oracles. Summaries reject mixed modes and conflicting manifest identity. Same-engine revision pairing requires full request equality; Rust/Pi pairing preserves meaningful tool schema differences and checks request-core equality. No fake delay or extra Pi work is introduced.

Correctness diagnostics use release dependencies with root Rust opt-level 0. Formal measurements require fixed normal optimized builds, fresh processes/stores, no compilation or profiling overlap, and paired interleaving. Seven pairs per case and metric in each mode remain required for a final parity claim. This harness checkpoint makes no performance claim.

Startup accounting is explicit: absolute self CPU/writes through cleanup include work before the first in-product endpoint (including module/test-harness initialization). Before-initialization-to-cleanup deltas remain separately named. Controller startup and total wall lifetime capture process launch/provider readiness as well. No startup cost is silently inferred to be zero.

Fresh steady-turn CPU signal profiles at the repaired production head separate both observation modes. Short-small/short-large have 271/293 signals without a live subscriber and 508/547 with one. Disjoint live ownership contains 124/123 read-domain signals and 119/147 publication-encoding signals. No read-domain signal appears in either unobserved profile, consistent with the explicit demand guard; a zero sampled count is not a proof of zero cost. SQL preparation is 65/57 and 103/113 signals respectively on a separate operation partition. These two partitions must not be added. Native observer consumer frames may be optimized into other stacks; zero separately classified consumer signals do not imply an absent consumer.

Single control/profile pairs only describe overhead: short-small CPU per measured turn is 36.56/35.63 ms without live observation and 73.75/70.00 ms with it; short-large is 38.44/38.13 ms and 75.31/75.00 ms. These include driver counter work, have 10 ms process tick resolution, and are neither repeated headline results nor before/after effects. Complete lifecycle counters include late full reads/verification/close/checkpoint/reopen/cleanup and remain separately available. No profiler-overhead subtraction is performed. Initial absolute Rust startup CPU falls below one tick in these samples and is reported as measured zero at that resolution, not as proof of zero startup work. Runtime evidence-file output remains outside the cleanup counter endpoint.

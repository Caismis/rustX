# Resource limits and recovery

This inventory is the policy audit for Issue #527. A KiB is 1,024 bytes and a MiB
is 1,048,576 bytes. The Workflow bound is exactly **16,777,216 bytes**, inclusive.
A package being accepted or a file being uploaded grants no extra preview,
extraction, execution-payload or model-context capacity.

## Cost and authority assumptions

Full content identity costs linear I/O. Each file inspection reads the complete
file twice with one reusable 64 KiB buffer, comparing SHA-256 rather than trusting
metadata timestamps. Package identities frame each path, length and verified
file digest, and staged publication verifies the resulting package again. A source capture's before/after directory
verification and package inspection can read unchanged selected bytes more than
once; these are related authorization scans, not a timestamp cache. Body size
never grows the retained Skill catalog. Python retains one anonymous captured
copy per owned snapshot and one installed source copy per prepared fingerprint,
plus the existing uv environment/cache. Snapshot clones share disk ownership;
prepared environments keep the existing store retention policy. Parsed metadata
and declarations can consume memory according to their semantic content; they
are not subject to a substituted whole-file byte ceiling.

Skill opening delimiters are recognized incrementally, so an impossible first
line is rejected without buffering the remaining malformed file. Python scans
requirements UTF-8, comments and whitespace with bounded state over the owned
capture, then reads only effective declaration spans. Raw comment/blank-line
length does not become retained declaration memory; capture read failures remain
storage failures. Missing Python entrypoint/requirements membership is rejected
immediately after name collection, before opening anonymous capture or streaming
any asset, including discovery and incomplete-observation evidence fallback.

Workflow clients serialize complete scratch operations per native client, before
encoding and through release, across request wrappers. Analysis admission checks
its generation/query owner again before encoding, after hashing and before native
analysis. Superseded queued operations consume no scratch; started transfers still
settle and release their owner. Workspace operations use the same browser-client
queue before Host HTTP encoding/dispatch. Native scratch work and Python Tool
catalog queries retain request/admission ownership through physical settlement
after connection close. Catalog queries also retain their listing permit through
cached source verification and inherit Host resource cancellation. Host drain
waits for these owners.

Model-choice paging reads only the admitted TOML documents and uses the same
strict native overlay and reread fence. Status/control requests do not hash a
package merely to expose its stored state. Blocking byte I/O runs under native
blocking owners. Cancellation is cooperative between chunks; in-progress OS I/O
and decoder/process settlement are awaited, not declared complete by dropping a
waiter. External source files remain mutable, and no atomic multi-file snapshot
is claimed. Verified frozen copies and Python anonymous capture determine the
bytes that may actually be used after authorization.
